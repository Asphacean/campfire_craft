<objective>
Stand up everything a session needs, and prove it against the live server: a toolchain that can actually compile Tauri 2 on this Pi, the refresh-token half of the auth service that makes AUTH-03 possible at all, and a real launcher window whose form logs a real person in and shows them the real server's status.

**Goal (quoted verbatim from ROADMAP.md Phase 4** — this Goal line is **not** in `As a` / `I want to` / `so that` user-story form, and nothing has been invented in its place. Run `/gsd mvp-phase 4` before execution if a formal user story is wanted; these plans do not need one, because the ROADMAP's five numbered Phase 4 success criteria already state the outcome in testable terms and are what every must-have here is derived from**):** *A friend goes from opening the launcher to playing on the server with no manual setup of Java, Forge, or mods.*

Purpose: this plan is the phase's tracer. It wires the thinnest real path — a form in a real window, through a Rust command, over a CA-pinned HTTPS client, into the live `campfire-auth` behind the live Caddy, back out as a token that is remembered in the OS credential store — and it does so on the operator's own machine, not against a mock. Everything the later waves add (files, Java, Forge, launch) hangs off this path.
Output: a `launcher/` Cargo workspace that builds a desktop binary, a `POST /api/refresh` endpoint live on the public front, and a window that says *Playing as Nick* after a real login.

## Claude's discretion, exercised here

| Choice | Decision taken | Why |
|--------|----------------|-----|
| Frontend stack | **No Node, no bundler, no npm dependency at all.** `launcher/ui/` is a plain `index.html` + `main.js` + `style.css` directory set as Tauri's `frontendDist`, with `app.withGlobalTauri` on so the frontend reaches Rust through `window.__TAURI__.core.invoke` and `window.__TAURI__.core.Channel` | 04-RESEARCH.md recommends vanilla TypeScript + Vite and argues for it with "one screen, no routing, no list rendering, no component reuse" — that same argument goes one rung further. Dropping the bundler removes the entire npm supply chain from this phase (including the `vite` **SUS** legitimacy verdict, which now needs no checkpoint because nothing is installed from npm), removes a build step from the operator's Windows and macOS build instructions, and costs one screen's worth of type checking. The Tauri CLI is taken from crates.io (`cargo install tauri-cli`, verdict OK, 25k downloads/week) instead of npm |
| Crate layout | A two-member workspace: `launcher/core` (`campfire-launcher-core`, a plain library with no Tauri dependency, plus one `campfire-cli` binary) and `launcher/src-tauri` (`campfire-launcher`, the thin window shell) | This is what makes the phase verifiable at all. Every hard part — manifest sync, Mojang downloads, the Forge install, the launch command — can then be exercised headlessly on this Pi with `cargo test` and `campfire-cli`, and the display-bound half shrinks to a form and a progress bar the operator checks on real hardware |
| Progress plumbing | The core takes a `&dyn Fn(Progress)` sink; only `src-tauri` adapts that to a `tauri::ipc::Channel` | Keeps the core Tauri-free (and therefore testable here) while still honouring D-07 exactly where it matters |
| `keyring` version | `^3` with the `apple-native`, `windows-native` and `linux-native` features | RESEARCH's recommendation. `linux-native` (the kernel keyutils backend) is what lets the credential round trip be a real, asserted test on this Pi: `/proc/keys` shows live session keyrings here, and there is no desktop secret-service daemon to depend on |
| `/api/refresh` rate limiting | One dedicated limiter, 60 attempts per hour per peer, counting every attempt | Mirrors the existing `login_success_limiter` shape. A refresh token is 32 random bytes, so there is no brute-force surface to defend — this limiter exists purely as a circuit breaker against runaway automation, and 60/hour is far above a real player pressing Play |
| Two HTTP clients, not one | `campfire_client()` disables built-in roots and adds only our CA; `public_client()` uses reqwest's bundled webpki roots and is the only client allowed to touch Mojang, Adoptium and Forge | `docs/DIST-OPS.md` makes pinning non-negotiable for our host, and Mojang obviously cannot be reached through our CA. Making them two named constructors means neither can be reached for by accident |
| Both Caddy edits at once | The `/api/refresh` proxy **and** the `/launcher/*` static tree (which wave 4 needs) go in together, so the whole phase costs one Caddy restart instead of two | Caddy runs with `admin off`, so every config change is a restart of the public HTTPS front |

## Service restarts this plan performs

- `campfire-auth` is rebuilt and restarted (`sudo systemctl restart campfire-auth`). It comes back in under a second and it fails closed: while it is down the auth-gate mod refuses joins rather than admitting them. Announce it in the SUMMARY; no player warning is needed for a sub-second gap.
- `caddy` is restarted once, which briefly drops the public HTTPS front (manifest, pack files, API). No game session is affected.
- **`rlcraft.service` is never stopped, restarted or reconfigured by this plan, and the Pi is never rebooted.**

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| The public internet → `/api/refresh` | A brand-new unauthenticated endpoint that mints game tokens, reachable by anyone who can route to the host |
| The launcher process → `mc.campfire.pub` | Where a MITM would substitute a forged server; the only defence is the pinned CA, because the manifest's hashes and the files come from the same place |
| The launcher process → the OS credential store | Where a 30-day credential comes to rest on a friend's machine |
| The person → the password field | The only place a plaintext password exists on the client side, and the one thing that must never be persisted |
| `launcher.log` → anyone reading it | A diagnostic file a friend will paste into Discord when something breaks |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01-01 | Spoofing | a forged `mc.campfire.pub` serving a forged token or manifest | critical | mitigate | `campfire_client()` disables reqwest's built-in root store and adds only the embedded `campfire-ca.pem`. Proven by `campfire-cli pin-check` requiring a certificate **failure** against a public-CA host with the same client — a pass-only test cannot distinguish pinning from ordinary TLS |
| T-04-01-02 | Information Disclosure | the refresh token written to a plaintext file instead of the OS credential store | high | mitigate | Only the `keyring` crate stores it; the acceptance criteria grep the entire scratch install root for the observed refresh value and require zero hits |
| T-04-01-03 | Information Disclosure | the password persisted, logged or echoed | critical | mitigate | The password is a function parameter and a request body and nothing else — no struct field outlives the call, the CLI reads it from stdin rather than argv, and the log is grepped for the literal password after a real login |
| T-04-01-04 | Information Disclosure | a token value in `launcher.log`, which friends paste into chat | high | mitigate | `log.rs` exposes a redaction helper and secrets are logged as a length and a marker; asserted by grepping the log for the exact token returned by a real login |
| T-04-01-05 | Elevation of Privilege | a stolen refresh token used indefinitely | high | mitigate | Every successful `/api/refresh` revokes the presented token in the same compare-and-swap that accepts it, capping a stolen token at one unrotated use; asserted by replaying a used token and requiring 401 |
| T-04-01-06 | Elevation of Privilege | a password reset that leaves remembered sessions alive | medium | mitigate | `campfire-auth reset` revokes every outstanding refresh row for that nick; asserted end to end in the smoke suite |
| T-04-01-07 | Information Disclosure | refresh tokens readable in the accounts database | high | mitigate | Stored only as argon2id PHC strings through the existing `auth::hash_secret`, in a table created under the same umask-0077 and chmod-600 path as the rest; asserted by dumping the column and requiring no raw value |
| T-04-01-08 | Denial of Service | `/api/refresh` hammered to mint tokens or spend argon2 cycles | medium | mitigate | A dedicated 60/hour/peer limiter reserved before any argon2 work, resolved through the existing loopback-only-trusted forwarded-for helper |
| T-04-01-09 | Spoofing | a client-supplied forwarded-for header shifting the rate limit onto someone else | medium | mitigate | The new Caddy handle copies the existing `header_up X-Forwarded-For {http.request.remote.host}` line verbatim, which sets rather than appends; `client_ip()` trusts the header only from a loopback peer |
| T-04-01-10 | Information Disclosure | the token-validation endpoint republished by a careless route addition | critical | mitigate | The new handles are exact paths inside the existing `route` block with no wildcard under `/api`; asserted by requiring a `404` from a public POST to the validation path after the restart |
| T-04-01-11 | Information Disclosure | launcher binaries published into the pack manifest and pushed to every client | medium | mitigate | The launcher static tree is rooted outside `PACK_DIR`, because the manifest generator walks everything under the pack root; asserted by publishing and requiring no manifest entry under the launcher prefix |
| T-04-01-12 | Denial of Service | the Caddy restart or the auth-service restart taking the game down | medium | accept | Neither touches `rlcraft.service`. `campfire-auth` fails closed for under a second — the auth-gate mod refuses joins rather than admitting them — and the Caddy gap affects only downloads. Every task asserts the game unit is still active and the boot time unchanged |
| T-04-01-13 | Tampering | the embedded CA drifting from the repository's CA after a rotation | medium | mitigate | A unit test compares the embedded bytes against `ca/campfire-ca.pem` whenever the repository copy is present, so a rotation that misses the launcher fails the build rather than shipping |
| T-04-01-SC | Tampering | package-manager supply chain | high | mitigate | **This plan installs nothing from npm** — no Node package manifest exists anywhere under `launcher/`, which is asserted, and which is what removes the `vite` **SUS** verdict from this phase entirely rather than waving it through. If the no-bundler frontend turns out not to work, the executor **stops and raises a checkpoint** rather than installing a bundler from npm without the legitimacy gate |
