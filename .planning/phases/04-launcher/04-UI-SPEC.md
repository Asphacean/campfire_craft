# Phase 4 — UI Design Contract

> Visual and interaction contract for the Tauri 2 desktop launcher. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no shadcn. Frontend is a Tauri 2 webview with vanilla TS/HTML/CSS (no React/Vue/Svelte), so shadcn's component registry model does not apply. Greenfield project, no `package.json`/`components.json` exists yet. |
| Preset | not applicable |
| Component library | none — hand-rolled semantic HTML + CSS. Window has ~8 interactive elements total; a component library adds a build step (framework, bundler config) for no reuse payoff at this scale. |
| Icon library | none. Two glyphs needed total: a status dot (CSS circle, no SVG) and a small "log" glyph on the "Open log" button (single inline `<svg>`, ~10 path points, authored once). No icon font/library dependency. |
| Font | System font stack: `-apple-system, "Segoe UI", system-ui, sans-serif`. No bundled webfont — avoids a network/asset dependency for a window that must render instantly on a cold launch, and gives each OS its native look for free. Tabular/monospace not needed (no data grids); version text and progress numbers use the same system stack. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (status dot to status text), input internal padding |
| sm | 8px | Gap between nick/password fields, gap between "Log in"/"Create account" buttons |
| md | 16px | Default padding around the form panel, gap between form and RAM slider |
| lg | 24px | Padding between panel edge and window edge |
| xl | 32px | Gap between RAM slider block and Play button |
| 2xl | 48px | Play button height context (button itself is 48px tall — primary touch target) |
| 3xl | 64px | not used at this window size — declared for scale completeness only |

Exceptions:
- Play button height fixed at 48px (not just padding) — it is the single most-pressed control in the app and must be unmissable in a 480×560 window; sized above the 44px minimum comfortable click target.
- Status pill and version text use compressed 4px vertical padding to stay unobtrusive (chrome, not content).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Usage:
- **Display (28/600):** the "campfire.pub" wordmark over the art background.
- **Heading (20/600):** collapsed logged-in state — "Playing as **Nick**" (nick itself renders at Heading weight, "Playing as" / "· Log out" at Label weight in the same line).
- **Body (16/400):** form inputs, button labels ("Log in", "Create account", "Play"), step label during progress.
- **Label (14/400):** status pill text, version/pack_version footer text, error banner body, "Open log" / "Game folder" / "Verify files" secondary button labels.

Only 4 sizes, 2 weights declared — no italics, no additional weight steps.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | RLCraft client-pack art (full-bleed background image) — **fallback `#14110F`** (near-black) if no usable art asset can be extracted from the cached client zip | Window background behind everything |
| Secondary (30%) | `#1C1815` at 82% opacity (dark warm-charcoal panel) | The form panel, RAM-slider block, and bottom progress/status bar — a single translucent panel anchoring all interactive content over the art so it reads as one system regardless of what's behind it |
| Accent (10%) | `#E08A3E` (ember/amber, campfire-themed) | Reserved for: the Play button (fill), the RAM-slider thumb + filled track, the status-pill "online" dot, the focus ring on all interactive elements. Nothing else uses this color. |
| Destructive/semantic | `#C6433D` (warm red, distinct from the amber accent) | Reserved for: the error banner background/left-border and its text, the RAM-slider fill when the >70% physical-RAM warning is active, the "offline" status-pill dot |

Accent reserved for: Play button fill, RAM-slider thumb/active-track, status-pill online dot, keyboard focus ring. Never used for body text, secondary buttons, or decorative elements.

Fallback rule: if the RLCraft art asset cannot be sourced/licensed cleanly at build time, the dominant surface is flat `#14110F` with the wordmark centered — same panel/accent colors apply unchanged, so the contract holds either way.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Play" (logged-in idle state) |
| Auth CTAs | "Log in" · "Create account" (same nick+password fields, two buttons side by side) |
| Collapsed logged-in state | "Playing as **{Nick}** · Log out" |
| Empty state (auth form, submit with a blank field) | "Enter a nickname and password." (inline, same red banner style as errors, appears only on submit attempt) |
| Loading state (auth) | Button label swaps to "Logging in…" / "Creating account…", both buttons disabled, no separate spinner graphic needed |
| Loading state (Play, syncing/downloading) | Step label above the progress bar: "{Step name} {done}/{total} · {rate}" e.g. "Downloading mods 120/187 · 45 MB/s"; Play button relabels "Launching…" and disables |
| Loading state (status pill, before first `/status` reply) | "● Checking…" in neutral gray, upgrades to Online/Offline once the first response lands |
| Error state — wrong password | "Wrong nickname or password. Open log" |
| Error state — server unreachable | "Can't reach campfire.pub. Check your internet connection. Open log" |
| Error state — Java download failed | "Couldn't set up Java. Open log" |
| Error state — disk full | "Not enough disk space to continue. Open log" |
| Error state — refresh session expired | "Your session expired — log in again." (form re-opens under this message, nick pre-filled) |
| Error state — file verify/repair | "Some files didn't match and were repaired." (informational banner, not red — success-toned, auto-dismisses after ~4s) |
| Update-available dialog | Title: "Update available" · Body: "Version {X.Y.Z} is ready." · Buttons: "Update now" (accent) / "Later" (text button) |
| RAM-slider warning | ">70% of your system RAM — this may slow down other apps." (appears under the slider in destructive/semantic color, not a blocking dialog) |
| Secondary buttons | "Game folder" · "Verify files" |
| Verify-files running state | Button label swaps to "Verifying…", disabled during the pass |
| Footer / version text | "Launcher {launcher_version} · Pack {pack_version}" |
| Destructive confirmation | Log out: no confirmation dialog — it only clears the local session, no data loss, so a single click is enough. No other destructive actions exist in this phase (Verify files is a re-check/repair, not deletion of user data). |

## UI Considerations

Applicable state considerations resolved: 13 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | auth form | ✅ covered | Submitting with a blank nick or password shows the inline "Enter a nickname and password." banner (see Copywriting Contract) instead of a silent no-op or disabled-button guess |
| loading | auth form | ✅ covered | Log in/Create account buttons disable and relabel "Logging in…"/"Creating account…" while the request is in flight; no spinner asset needed |
| loading | Play button / progress bar | ✅ covered | Step label + progress bar (Tauri channel-driven, per PITFALLS #8) shows live step name, count, and rate; Play relabels "Launching…" and disables for the whole sync→install→launch sequence |
| loading | status pill | ✅ covered | Shows "● Checking…" (neutral) until the first `/status` response lands, then Online/Offline |
| loading | media (art background) | ✅ covered | Art is bundled as a build-time asset (embedded, not fetched over the network), eliminating any runtime loading state for the background — it is always present on first paint |
| error | auth form | ✅ covered | Red inline banner with the specific message (wrong password, server unreachable, etc.) + "Open log" button, per Copywriting Contract |
| error | Play / sync-download flow | ✅ covered | Same red banner pattern; Play failure never leaves the progress bar stuck — it stops and shows the error with "Open log" |
| error | status pill | ✅ covered | Fetch failure (timeout/network error) renders "● Offline" in the destructive color; Play remains enabled per the locked decision (offline doesn't block Play) |
| error | update-check (self-update) | ✅ covered | A failed update check is silent (no dialog, no banner) — self-update is a convenience, not a blocking dependency for Play; only a successful check that finds a newer version shows the dialog |
| error | Apple Silicon Rosetta / Java setup | ✅ covered | If the x86_64 Java 8 fails to run under Rosetta (Rosetta not installed or broken), it surfaces through the same "Couldn't set up Java. Open log" error state — no separate first-run wizard; the log names the real cause for the operator to diagnose |
| partial | auth form | ✅ covered | A single filled field (nick without password, or vice versa) surfaces the same "Enter a nickname and password." message on submit — it does not attempt partial validation per-field |
| long-text | auth form (nick field) | 🧪 backstop | Nick input has a `maxlength` matching the auth service's registration limit so overflow can't occur in the field itself; the collapsed "Playing as **{Nick}**" heading truncates with ellipsis past ~20 characters if a longer legacy nick exists — needs a rendered-width check against the actual max nick length once auth-service validation rules are read during planning |
| long-text | error banner | ✅ covered | Error banner text wraps to a maximum of 2 lines with a fixed max-width matching the panel; anything longer is truncated with "…" and the full detail is always available via "Open log" |
| overflow | error banner | ✅ covered | Same 2-line wrap/truncate rule as long-text above (single resolution covers both) |
| zero-one-many | n/a | ✅ covered | No list-collection element exists in this window (no file list, no player list is rendered — progress is an aggregate count "120/187", not an enumerated list), so this category does not apply |
| unclassified | RLCraft art + wordmark (media) | 🧪 backstop | Classified as `media`, but "usable art can't be sourced" fallback (dark minimalism, per CONTEXT.md) needs a go/no-go decision during planning once the actual client-pack art asset is inspected for extractability and licensing — the visual contract (colors/spacing/type) holds under either outcome, but which asset ships is not yet decided |

## Accessibility Basics

- **Keyboard focus order:** Nick field → Password field → Log in → Create account → (after login) RAM slider → Play → Game folder → Verify files → Log out. Tab order follows visual top-to-bottom, left-to-right reading order; no positive `tabindex` overrides.
- **Focus indicator:** every focusable element gets a 2px solid accent-color (`#E08A3E`) outline with 2px offset — visible on both the art background and the dark panel (accent has ≥ 4.5:1 contrast against both `#14110F` and `#1C1815`).
- **Contrast over art:** all text sits on the 82%-opacity `#1C1815` panel, never directly on raw art pixels — this guarantees ≥ 4.5:1 body-text contrast regardless of how bright/busy the underlying art image is, so contrast does not depend on which art asset ships.
- **Error not color-only:** every error/warning is red AND carries an explicit leading label ("Wrong nickname or password…", the RAM warning's own sentence, etc.) — color reinforces, never carries, the meaning. Status pill likewise pairs color with text ("Online"/"Offline"/"Checking…"), not a bare colored dot.
- **Non-resizable window:** fixed ~480×560 means no responsive reflow contract is needed — layout is authored once at this exact size.
