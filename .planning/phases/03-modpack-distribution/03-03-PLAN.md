    Then check locally before checking publicly, so a local fault is never misreported as a router fault. Request the manifest through the loopback path with the CA pinned; a non-200 here means Caddy or the manifest is broken and the verdict is a plain FAIL naming that, with an exit status of 1, and the public check is not attempted at all.

    Then check the public path. Use `curl` with `--resolve` binding the domain and the HTTPS port to the **resolved public address**, and `--cacert` pointing at the repo's CA.     A 200 with a parseable manifest body is `VERDICT: PASS` with exit 0 — the port is forwarded and NAT hairpin works, so this is proof of public reachability from the Pi itself.

    A connection refused, reset or timeout is **not** a failure verdict, because this Pi sits behind the same NAT as the server and many consumer routers simply do not hairpin. Print `VERDICT: INCONCLUSIVE` and exit 2, and print the exact steps a human takes to settle it: from a phone on mobile data with Wi-Fi off, open the manifest URL in a browser and expect a certificate warning followed by JSON, or run an `openssl s_client -connect` against the domain and port from any machine outside the home network and expect a certificate whose subject alternative name is the domain. Say plainly in that message that a certificate warning in a browser is the expected and correct outcome here, because the CA is private and only the launcher pins it — so a warning followed by JSON is a pass, not a problem.

    Anything else — a TLS handshake failure, a wrong-certificate error, or an HTTP status that is not 200 — is `VERDICT: FAIL` with exit 1 and the observed detail, because those mean the connection got through and something on our side is wrong.

    Update the script's header comment to describe the new mode and the three exit statuses, and update its usage line.

### HTTPS route table (as published to the internet)

Base URL: `https://mc.campfire.pub:8444`. Trust anchor: `ca/campfire-ca.pem`, pinned, with built-in roots disabled.

| Public route | Method | Reaches | Returns |
|---|---|---|---|
| `/manifest.json` | GET, HEAD | `~/rlcraft/pack/manifest.json` | The pack contract |
| `/pack/<url>` | GET, HEAD | `~/rlcraft/pack/<url>` | A managed file; `<url>` is a `files[].url` verbatim |
| `/api/register` | POST | `127.0.0.1:8081/register` | 201, or 400/409/429 with a stable error code |
| `/api/login` | POST | `127.0.0.1:8081/login` | `{token, expires}`, or 400/401/429 |
| `/status` | GET | `127.0.0.1:8081/status` | `{online, players, max, motd}`; offline is HTTP 200 with `online:false` |
| anything else | any | — | 404 |
| non-GET/HEAD on the static routes | — | — | 405 |

The token-validation endpoint has no public route. It is unauthenticated beyond the token itself and deliberately never rate limited because it is the join path; its only legitimate caller is the auth-gate mod over loopback.

### manifest.json schema (D-08)

`{ "pack_version": "<ISO-8601 UTC timestamp>", "mc": "1.12.2", "forge": "14.23.5.2860", "java": 8, "files": [ { "path": "mods/Example-1.0.jar", "sha256": "<64 lowercase hex>", "size": 49537, "url": "mods/Example-1.0.jar" } ], "delete": [ "mods/Removed-0.9.jar" ] }`

Managed: `mods/`, `config/`, `scripts/`, `resources/`, `structures/`, `resourcepacks/`. Never managed and never deleted: `saves/`, `screenshots/`, `logs/`, `crash-reports/`, `options.txt`, `optionsof.txt`, `servers.dat`. The `delete` array is cumulative, so a client several publishes behind still learns about an old removal.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → the router → the Pi | This plan is the act of opening this boundary; what crosses it is decided entirely by the shape of one forwarding rule |
| The Pi's own name resolution → any reachability check | `/etc/hosts` maps the domain to loopback, so a check that trusts DNS on this host measures nothing about the public path |
| The published contract → the Phase 4 launcher | A document that tells a future implementer what to trust; an omission here becomes a security hole three phases later |
