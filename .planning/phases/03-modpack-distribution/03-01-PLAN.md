## Phase 3 Decision IDs

These IDs are local to Phase 3, derived from `03-CONTEXT.md`. They are numbered independently of Phase 1's and Phase 2's D-numbers.

| ID | Decision (from 03-CONTEXT.md) |
|----|-------------------------------|
| D-01 | HTTPS lives on TCP 8444 on `mc.campfire.pub`; :443 (sing-box) and :80/:8443 (pbwiki) are never touched; the router forward for 8444 is an operator action behind a checkpoint |
| D-02 | TLS is an own private CA: `ca/campfire-ca.pem` tracked, `ca/campfire-ca-key.pem` mode 600 and gitignored and backed up; leaf for `mc.campfire.pub`; 10-year CA, ~2-year leaf; `scripts/renew-cert.sh` |
| D-03 | Caddy on the HOST from the official Caddy apt repo (`caddy.service`); Caddyfile tracked at `caddy/Caddyfile`; installed by `scripts/install-caddy.sh`; `auto_https off`, explicit `tls`, admin off |
| D-04 | Routes on :8444: `/api/register`, `/api/login`, `/status` proxy to 127.0.0.1:8081; the token-validation endpoint is never routed; `/manifest.json` and `/pack/*` are a `file_server` rooted at `~/rlcraft/pack/`, GET/HEAD only, no directory browsing, no dotfiles |
| D-05 | Registration rate limiting stays in the auth service |
| D-06 | Client pack base is the official RLCraft 2.9.3 **client** zip from CurseForge, overlaid with `server/config/` and the `campfire-auth-*.jar` from `server/mods/` |
| D-07 | Every mod, config, script and resource is self-hosted; no CurseForge API key and no per-mod license audit; DIST-03 is weakened to "the Minecraft client jar, libraries and assets are never served from our host" |
| D-08 | `manifest.json` is `{pack_version, mc, forge, java, files:[{path, sha256, size, url}], delete:[]}`; `url` is relative to `/pack/`; managed dirs are `mods/`, `config/`, `scripts/`, `resources/`, `structures/` plus whatever the client zip's overrides carry; never `saves/`, `options.txt`, `servers.dat`, `screenshots/`, `logs/` |
| D-09 | `pack/` is a gitignored staging dir; `scripts/publish-pack.sh` is the single operator command; the manifest is written atomically and `delete[]` is diffed against the previous manifest |
| D-10 | Mods are fetched by projectID/fileID from the unauthenticated CurseForge CDN; a blocked file is reported and the operator resolves it by hand |
| D-11 | `GET /status` in the auth service performs a real Minecraft Server List Ping against 127.0.0.1:25565, caches for 10 s, returns `{online, players, max, motd}`; unreachable means `{online:false}` with HTTP 200 |
| D-12 | `pack/` is not backed up; the `ca/` key and `caddy/Caddyfile` are added to `scripts/backup.sh` |
| D-13 | `scripts/assemble-client.py` builds and hash-verifies a client from the manifest on the Pi as the automated proof of manifest correctness; the real play test is a human check deferred until the launcher exists |
| D-14 | `~/pbwiki` and sing-box are not modified in any way; the HTTPS surface stays minimal — no listing, no writes, no auth-service admin routes |

This plan implements D-01 (the listener half), D-02, D-03, D-04, D-05, D-11, D-12 and D-14.

## Claude's discretion, exercised here

| Choice | Decision taken |
|--------|----------------|
| Caddy version | Whatever the official Cloudsmith `stable` repo resolves to in the 2.11.x family; not Debian's bundled 2.6.2 |
| Cert tooling | Plain `openssl`, ECDSA P-256, exactly the chain RESEARCH.md ran end-to-end on this host; not `tls internal`, not `mkcert` |
| `/api` path mapping | Caddy strips the `/api` prefix, so the auth service's own route table is unchanged from Phase 2. Only two explicit paths are stripped — there is no `/api/*` wildcard, because a wildcard would publish the token-validation endpoint |
| CA + leaf in one script | `scripts/renew-cert.sh` creates the CA if it does not exist and always re-issues the leaf. One command, not two |
| Name resolution on the Pi | `/etc/hosts` maps `mc.campfire.pub` to 127.0.0.1 so every tool on the Pi reaches the local Caddy under the certificate's own name. Outside-in checks in plan 03-03 use `curl --resolve` against the public IP, which ignores `/etc/hosts` |
