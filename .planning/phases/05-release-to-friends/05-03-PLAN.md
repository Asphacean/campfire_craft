<objective>
Turn a release into something a friend can use, and write down the one thing only real hardware can answer.

**Goal (quoted from ROADMAP.md Phase 5):** *Friends get the launcher from a link and run it, on both Windows and macOS.*

**This plan's slice of that story:** *the "and run it" half.* 05-02 produced installers; this plan proves they are actually reachable the way a friend reaches them, writes the page that walks a friend past the two operating-system warnings that would otherwise stop them dead, and hands the operator a checklist for the parts of REL-02 and REL-03 that cannot be answered by anything on this Pi — no display, no Windows, no Mac.

Purpose: REL-02 (the unsigned-macOS build plus the written Gatekeeper bypass) and REL-03 (Apple Silicon, verified on real hardware).
Output: `docs/FRIENDS.md`, a real `README.md`, a release procedure rewritten around the pipeline, and a QA matrix that also reopens the Phase 1-4 verifications this release finally unblocks.

Decision IDs implemented here: **D-07, D-08, D-10, D-11** (the table is in `05-01-PLAN.md`'s objective).

## What this plan may not do

REL-03 asks whether the launcher works on Apple Silicon. That question has exactly one honest answer available from a headless Pi: *unknown, and here is precisely how to find out.* Nothing in this plan may claim, imply or infer that a Mac ran anything. The macOS checks in Task 1 are file-shape checks — what is inside the bundle — and they are labelled as such. Intel macOS goes further: no Intel hardware exists for this project at all, so its artifact is built-and-unverified, and D-11 says to record that rather than dress it up.
