<objective>
Open the door, then walk one tag all the way through it.

**Goal (quoted from ROADMAP.md Phase 5):** *Friends get the launcher from a link and run it, on both Windows and macOS.*

**This plan's slice of that story:** *the link exists and it points at real installers.* After this plan, a friend who is told the URL can download a Windows installer or a Mac disk image that was built today by a machine neither of you owns — the last task here is the phase's tracer, one thin path through every layer at once: a tag on the Pi, three GitHub-hosted build legs, a Release, the Pi's own publish runner, the signing key that never left this house, and the feed Caddy serves.

Purpose: REL-01 in full — a tag produces the builds — plus the two one-way doors this phase contains (a public repository holding this project's entire history, and the first push of that history), which sit behind human checkpoints rather than behind an autonomous decision.

Output: a public repository with green CI, a third runner on the Pi, the `v0.1.0` release, and a live feed carrying three real signed platforms.

Decision IDs implemented here: **D-01, D-02, D-03, D-04, D-05, D-12** (the table is in `05-01-PLAN.md`'s objective). The tracer is the first thing in this phase that is end-to-end, because the two layers ahead of it — a public remote and a registered runner — cannot exist until a human opens them.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → self-hosted runner on the Pi | Anyone can fork a public repository; a fork-triggered workflow reaching the `campfire-publish` label would be shell access to the operator's home directory |
| GitHub Release assets → the Pi's publish job | The Pi executes a script over files downloaded from the internet and signs the results with its private key |
| Operator's tag → the whole pipeline | A tag push is the only authorisation the release path requires |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-04 | Elevation of Privilege | `gh-runner-campfire` on a public repository | high | mitigate | Two independent locks: no fork-triggerable event exists in either workflow (grep-gated in 05-01), and the repository setting requiring approval for outside contributors is confirmed by the operator in this plan's human-action checkpoint. The self-hosted job runs only in the tag-triggered workflow, and only write access can push a tag |
